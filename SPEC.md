3. Правила длинных нард — реализовать в точности
3.1 Доска, расстановка, направление

Доска: 24 пункта. У каждого игрока 15 шашек. Используй абсолютную нумерацию пунктов 1–24 (белая перспектива) и функции конвертации в «собственную» нумерацию каждого игрока (у каждого игрока свой отсчёт: его голова = его пункт 24, его дом = его пункты 1–6, движение по убыванию 24→1):

Белые: собственный пункт n = абсолютный n. Голова — абс. 24, дом — абс. 1–6.
Чёрные: абсолютный пункт = ((n + 11) % 24) + 1, где n — собственный номер. Голова — абс. 12, дом — абс. 13–18. Старт: все 15 белых на абс. 24, все 15 чёрных на абс. 12. Оба игрока движутся в одном круговом направлении, шашки соперников никогда не «встречаются лоб в лоб» — они идут по одному кольцу со сдвигом в полкруга.

Кодировка состояния в narda_core: List<int> points длиной 24 (положительные — количество белых, отрицательные — чёрных), int whiteBorneOff, int blackBorneOff, Player turn, List<int> remainingDice. Состояние иммутабельно; apply(move) возвращает новое.

3.2 Ход
Первый ход партии: каждый бросает один кубик, у кого больше — ходит первым (при равенстве перебрасывают); первый ходящий бросает оба кубика заново.
Бросаются 2 кубика. Обычный бросок — два перемещения (по одному на кубик, можно одной шашкой последовательно). Дубль — четыре перемещения этим числом.
Перемещение: шашка идёт на N пунктов вперёд по своему маршруту (в собственной нумерации: с пункта p на пункт p−N).
Нельзя ставить шашку на пункт, занятый хотя бы одной шашкой соперника. Битья не существует. На своём пункте — сколько угодно своих шашек.
Правило головы: за один ход (весь бросок целиком) с головы можно снять только ОДНУ шашку. Исключение — самый первый бросок партии этого игрока: если выпал дубль 6-6, 4-4 или 3-3, разрешено снять с головы ДВЕ шашки (одной шашкой такой дубль полностью не сыграть — путь перекрыт головой соперника).
Обязательность полного хода: игрок обязан использовать оба числа (при дубле — максимум возможных из четырёх). Если можно сыграть только одно из двух чисел — обязан сыграть большее из игрАбельных. Если нет ни одного легального перемещения — ход пропускается (UI показывает «yurish yo'q»). Генератор ходов обязан возвращать только максимальные последовательности (нельзя «сыграть меньше, когда можно больше»).
Правило блока (шести подряд): запрещено делать перемещение, после которого образуется 6 и более подряд занятых твоими шашками пунктов, если ПЕРЕД этим блоком (по направлению движения соперника) не остаётся ни одной шашки соперника. Т.е. запирать все 15 шашек соперника «глухим забором» нельзя; если хотя бы одна его шашка уже впереди блока — блок легален.
3.3 Выброс (chiqarish)

Когда все 15 шашек игрока в его доме (собств. пункты 1–6), он может выбрасывать: шашка с пункта k выбрасывается точным числом k; если выпавшее число больше номера самого дальнего занятого пункта — можно выбросить шашку с этого самого дальнего пункта; вместо выброса можно (если есть легальный ход) передвигать шашки внутри дома. Обязательность из п. 3.2.6 сохраняется.

3.4 Результат

Победа — все 15 шашек выброшены первым. Oyin = 1 очко; Mars = 2 очка (соперник не выбросил ни одной). Матчи: одиночная партия или серия до 3 / 5 / 7 очков (выбор при старте). Сдача партии разрешена (соперник получает 1 очко, при явном марсе — 2: если у сдавшегося 0 выброшенных — 2 очка).

4. Бот

В narda_core. Через полный генератор легальных последовательностей: для каждой последовательности оценивать итоговое состояние эвристикой и выбирать лучшую. Эвристика (веса вынеси в конфиг): суммарный pip-прогресс; ценность блоков из подряд идущих пунктов, особенно на пути выхода соперника с головы (абс. 9–11 против чёрных / 21–23 против белых — «перехват»); раннее развитие головы; штраф за высокие «свечки» (5+ на одном пункте); равномерное заполнение дома к выбросу; эффективность выброса. Три уровня: Oson (случайный из топ-50% ходов), O'rta (лучший ход c шумом), Kuchli (лучший ход; допускается 2-ply: перебор ожиданий по 21 исходу костей соперника, если укладывается в < 200 мс на ход). Бот не подглядывает будущие кости.

6. Онлайн (P4) — протокол

Firebase: анонимная авторизация, Realtime Database. Комнаты: приватная по 6-значному коду и быстрый матч (очередь matchmaking/{uid} со спариванием транзакцией первого ожидающего). Схема:

rooms/{roomId}/
  meta:    {createdAt, matchTarget, status: waiting|playing|finished, code}
  players: {uid: {name, color}}
  state:   {points: <encoded>, turnUid, dice, remainingDice, whiteOff, blackOff, moveIndex, deadline}
  moves/{index}: {uid, dice, seq: [[fromAbs, die], ...], ts: SERVER_TIMESTAMP}
  presence/{uid}: bool (onDisconnect → false)

Принципы:

Ходы пишет только игрок, чей ход (security rules: auth.uid == state.turnUid, игроки комнаты — только из players). Оба клиента прогоняют каждый входящий ход через narda_core; нелегальный ход или расхождение хеша состояния → пересборка состояния реплеем moves/ с нуля; если и реплей нелегален — партия аннулируется с сообщением.
Реконнект: состояние всегда восстановимо реплеем лога ходов. Presence через onDisconnect; при отсутствии соперника 60 сек — предложение «завершить с победой» (клейм по серверному времени, оффсет через .info/serverTimeOffset).
Таймер хода 60 сек (deadline по серверному времени). Просроченный ход — автопас; 2 подряд просроченных — поражение.
Кости в v1 генерирует клиент активного игрока и записывает в moves/ (честное ограничение MVP; задача «серверные кости через Cloud Function» — в backlog, в код заложи точку замены DiceSource). НЕ выдавай ботов за живых игроков в онлайне; если очередь пуста > 15 сек — честно предложи «сыграть с ботом, пока ищем».
Общение — только предустановленные фразы и эмодзи-реакции (никакого свободного чата — не нужна модерация): «Salom!», «Yaxshi yurish!», «Omad!», «Rahmat, yaxshi o'yin», 👍😄😮🎲.
