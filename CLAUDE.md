# CLAUDE.md

Инструкции для Claude Code по этому репозиторию.

## Что это

«Uzun narda» — длинные нарды для Android с узбекским интерфейсом.
**Источник истины — [SPEC.md](SPEC.md)**: правила игры (§3), бот (§4), фазы (§5),
онлайн-протокол (§6), внешний вид и локализация (§7). Перед изменениями правил
или UI сверяйся со спекой, а не с памятью о бэкгаммоне.

Ключевое: это НЕ короткие нарды. Битья нет, бара нет, куба удвоения нет.
Оба игрока идут по одному кольцу со сдвигом в полкруга.

## Процесс

- Одна фаза за раз. В конце фазы: `flutter analyze` чисто, тесты зелёные,
  короткий отчёт (что сделано / как проверить / что дальше), ждать подтверждения.
- Коммит на каждую фазу.
- Не добавлять фич сверх спеки; при неоднозначности — спрашивать.
- Общение по-русски, комментарии в коде по-русски, идентификаторы английские.
- Строки UI — только через ARB. Узбекская латиница — язык по умолчанию,
  русский — второй. Машинно-переведённые узбекские строки помечать в отчёте.

Статус: P1 (ядро) и P2 (играбельный оффлайн) готовы. Дальше P3 — публикуемая
версия. P4 (онлайн, Firebase) — только после явного «поехали»; до P4 в проекте
не должно быть ни одной зависимости от Firebase.

## Структура

```
packages/narda_core/   чистый Dart: состояние, правила, генератор ходов, бот
app/                   Flutter: доска на CustomPaint, экраны, локализация
```

Три слоя (главное архитектурное требование, §2):

1. `narda_core` — **ни одного импорта Flutter**. Правила и бот живут только здесь.
2. UI — Flutter, доска на `CustomPaint`, никаких игровых движков.
3. Слой соперника — `Opponent` (`app/lib/game/opponent.dart`) с реализациями
   `HotseatOpponent`, `BotOpponent`, в P4 добавится `OnlineOpponent`.
   UI не знает, с кем играет: он спрашивает только `movesOnThisDevice`.

## Команды

```bash
# ядро
cd packages/narda_core
dart analyze && dart test
NARDA_PROPERTY_GAMES=200 dart test        # быстрый прогон property-тестов
dart run bin/selfplay.dart --seed=42       # партия бот-против-бота в ASCII

# приложение
cd app
flutter analyze && flutter test
flutter gen-l10n                           # после правки ARB
flutter run                                # Android, portrait
```

## Что стоит знать по коду

- **Генератор ходов отдаёт только максимальные последовательности** и схлопывает
  перестановки с одинаковым результатом. Поэтому доска собирает ход через
  `TurnPlanner` (`app/lib/game/turn_planner.dart`): перемещение разрешено, если
  после него всё ещё достижима максимальная длина хода, а перед применением ход
  приводится к варианту ядра через `canonicalSequence`.
- **Перспектива доски.** `BoardGeometry` раскладывает пункты в собственной
  нумерации нижнего игрока: 1–6 — низ справа (дом), 13–24 — верхний ряд,
  голова (собств. 24) — верхний правый угол. В hotseat доска переворачивается
  сменой `perspective`.
- **Бот считается в изоляте** (`compute`) — состояние передаётся строкой
  `GameState.encode()`, ход возвращается парами `fromAbs, die`.
- **Локализация.** `AppText.supportedLocales` отсортирован по алфавиту (ru, uz),
  поэтому язык по умолчанию задаётся через `resolveNardaLocale` в `app/lib/app.dart`.
  Без него на любом «чужом» языке устройства включался бы русский.
- **Форматирование.** Репозиторий намеренно не прогнан через `dart format`
  (стиль расставлен вручную). Не запускай форматтер по всему проекту.
- Кости в ядре берутся из `DiceSource` — это точка замены для серверных костей
  в P4, не обходить её.
- **minSdk.** Спека просит 23, фактически стоит минимум Flutter (24): tool сам
  переписывает литерал `minSdk = 23`, а `shared_preferences_android` требует 24.
  Не «чинить» это — вопрос открыт для владельца проекта.
